The last-login-method integration floats a compact "Last" indicator over the matching username, email, or social sign-in control. It reads the method after hydration, so server-rendered auth pages do not produce a hydration mismatch.

## Setup

<Steps>

<Step>
### Add the Better Auth server plugin

Add Better Auth's [Last Login Method](https://www.better-auth.com/docs/plugins/last-login-method) plugin to your server configuration:

```ts title="lib/auth.ts"
import { betterAuth } from '@vezham/auth'
import { lastLoginMethod } from '@vezham/auth/plugins'

// [!code highlight]

export const auth = betterAuth({
  // ...
  plugins: [
    lastLoginMethod() // [!code highlight]
  ]
})
```

</Step>

<Step>
### Add the matching client plugin

Add `lastLoginMethodClient()` to the client passed to `<Auth.Provider>`:

```ts title="lib/auth-client.ts"
import { lastLoginMethodClient } from '@vezham/auth/client/plugins'
import { createAuthClient } from '@vezham/auth/react'

// [!code highlight]

export const authClient = createAuthClient({
  plugins: [
    lastLoginMethodClient() // [!code highlight]
  ]
})
```

</Step>

<Step>

### Register the UI plugin

Register `LastLoginMethod.plugin()` with the Vezham auth provider:

```tsx title="components/providers.tsx"
import { Auth } from '@vezham/react/auth'
import { LastLoginMethod } from '@vezham/react/auth/plugins/last-login-method'

// [!code highlight]
;<Auth.Provider
  authClient={authClient}
  navigate={navigate}
  plugins={[
    LastLoginMethod.plugin() // [!code highlight]
  ]}>
  {children}
</Auth.Provider>
```

</Step>

</Steps>

The sign-in view now marks the username or email control, or the matching social provider, when Better Auth has stored a previous method. Sign-up controls do not show the indicator.

## Localization

Override the full and compact labels through the UI plugin:

```tsx
LastLoginMethod.plugin({
  localization: {
    lastUsed: 'Previously used',
    lastUsedShort: 'Previous'
  }
})
```

```tsx title="LastLoginMethodPluginOptions"
type LastLoginMethodPluginOptions = {
  /**
   * Override the plugin's default localization strings.
   * @remarks `LastLoginMethodLocalization`
   */
  localization?: Partial<LastLoginMethodLocalization>
}
```

```tsx title="LastLoginMethodLocalization"
type LastLoginMethodLocalization = typeof lastLoginMethodLocalization
```

## Custom methods

Better Auth tracks email and social providers by default. If `customResolveMethod` stores another method, place `<LastLoginMethod.Badge />` beside its sign-in control:

```tsx
import { LastLoginMethod } from '@vezham/react/auth/plugins/last-login-method'

;<LastLoginMethod.Badge method="magic-link" />
```

Pass an array when one control represents more than one stored method:

```tsx
<LastLoginMethod.Badge method={['email', 'username']} />
```

## Cookie consent

Whether the plugin's browser-readable cookie is non-essential and requires consent depends on your jurisdiction and how your application uses it. Consult qualified legal counsel for guidance. When consent is required, configure Better Auth's `beforeStoreCookie` option to return a stored user-consent flag or an equivalent condition. Authentication still works when the hook returns `false`.
