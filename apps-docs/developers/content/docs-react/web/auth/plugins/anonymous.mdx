The anonymous UI plugin contributes one "Continue as guest" button to the authentication forms. A successful sign-in refreshes the session and follows the `redirectTo` configured on `<Auth.Provider>`.

## Setup

<Steps>

<Step>

### Configure the Better Auth server plugin

Add Better Auth's [Anonymous](https://www.better-auth.com/docs/plugins/anonymous) plugin:

```ts title="lib/auth.ts"
import { betterAuth } from '@vezham/auth'
import { anonymous } from '@vezham/auth/plugins'

// [!code highlight]

export const auth = betterAuth({
  // ...
  plugins: [
    anonymous() // [!code highlight]
  ]
})
```

Run the Better Auth migration command so the user table includes `isAnonymous`:

```bash
pnpm dlx @better-auth/cli migrate
```

</Step>

<Step>
### Configure the Better Auth client plugin

Add `anonymousClient()` to the browser client:

```ts title="lib/auth-client.ts"
import { anonymousClient } from '@vezham/auth/client/plugins'
import { createAuthClient } from '@vezham/auth/react'

// [!code highlight]

export const authClient = createAuthClient({
  plugins: [
    anonymousClient() // [!code highlight]
  ]
})
```

</Step>

<Step>

### Register the Vezham Auth plugin

Pass `Anonymous.plugin()` to `<Auth.Provider>`:

```tsx title="components/providers.tsx"
import { Auth } from '@vezham/react/auth'
import { Anonymous } from '@vezham/react/auth/plugins/anonymous'

// [!code highlight]
;<Auth.Provider
  authClient={authClient}
  navigate={navigate}
  plugins={[
    Anonymous.plugin() // [!code highlight]
  ]}>
  {children}
</Auth.Provider>
```

</Step>

</Steps>

## Change the label

Override the plugin localization when the default wording does not fit your product:

```tsx
Anonymous.plugin({
  localization: {
    continueAsGuest: 'Explore as a guest'
  }
})
```

```tsx title="AnonymousPluginOptions"
type AnonymousPluginOptions = {
  /**
   * Override the plugin's default localization strings.
   * @remarks `AnonymousLocalization`
   */
  localization?: Partial<AnonymousLocalization>
}
```

This integration only adds guest entry. If your application later lets guests create a permanent account, configure Better Auth's server-side `onLinkAccount` callback to move application data to the new user.
