## Installation

`@vezham/react` contains the Vezham UI. Better Auth owns the server, session cookies, database, email delivery, permissions, and provider credentials. [Configure a Better Auth server](https://better-auth.com/docs/installation) and mount its handler before using these components.

```bash
pnpm add @vezham/react '@vezham/auth@npm:better-auth@1.7.2' '@vezham/auth-passkey@npm:@better-auth/passkey@1.7.2'
```

`@vezham/auth-ui-core` and `@vezham/auth-ui-react` are local workspace packages containing the configuration, validation, queries, mutations, hooks, and server helpers used by the UI. They have no Better Auth UI package dependency. `@vezham/auth` and the optional engine plugin SDKs remain npm aliases; those targets can switch to Vezham OSS forks without changing application imports. Outside this workspace, use the explicit engine alias installation above until those forks are published.

Load the workspace's normal Vezham styles. For a standalone application, include Tailwind v4, Vezham v3 styles, and `@vezham/react` styles. Auth uses the existing package stylesheet and requires no additional styling provider.

## Usage

```tsx
'use client'

import { passkeyClient } from '@vezham/auth-passkey/client'
import { twoFactorClient } from '@vezham/auth/client/plugins'
import { createAuthClient } from '@vezham/auth/react'
import { Auth } from '@vezham/react/auth'
import { Passkey } from '@vezham/react/auth/plugins/passkey'
import { TwoFactor } from '@vezham/react/auth/plugins/two-factor'

const authClient = createAuthClient({
  plugins: [passkeyClient(), twoFactorClient()]
})

export const SignInPage = () => (
  <Auth.Provider
    authClient={authClient}
    navigate={({ to, replace }) =>
      replace ? window.location.replace(to) : window.location.assign(to)
    }
    redirectTo="/dashboard"
    plugins={[Passkey.plugin(), TwoFactor.plugin()]}>
    <Auth view="signIn" />
  </Auth.Provider>
)
```

Register each feature at three matching boundaries: the Better Auth server plugin, its client plugin (when required), and the Vezham UI plugin in `Auth.Provider`. UI registration does not grant permissions or configure server endpoints. The [Better Auth plugin guide](https://better-auth.com/docs/concepts/plugins) describes that contract.

## Provider

| Prop                      | Description                                                                      |
| ------------------------- | -------------------------------------------------------------------------------- |
| `authClient`              | Your typed Better Auth client. Required.                                         |
| `navigate`                | Router adapter receiving `{ to, replace, view, params }`. Required.              |
| `queryClient`             | Optional application TanStack Query client; otherwise the provider resolves one. |
| `plugins`                 | Feature registrations from the subpaths below.                                   |
| `basePaths`               | Auth, settings, and organization route bases.                                    |
| `viewPaths`               | View names mapped to route segments.                                             |
| `redirectTo`              | Successful authentication destination.                                           |
| `emailAndPassword`        | Password, confirmation, verification, and remember-me options.                   |
| `socialProviders`         | Configured OAuth providers and optional custom icons.                            |
| `locale` / `localization` | Locale bundle or message overrides.                                              |
| `additionalFields`        | Typed additional sign-up/profile fields and validation.                          |
| `profile`                 | Profile and avatar editing configuration.                                        |

The exported `AuthProviderProps` preserves the headless provider's complete, generic configuration. Keep `authClient` and an explicitly supplied `queryClient` stable across renders.

Try the [sign-in](/docs/ui/react/web/auth/components/auth/sign-in), [sign-up](/docs/ui/react/web/auth/components/auth/sign-up), and [security settings](/docs/ui/react/web/auth/components/settings/security/security-settings) examples.
