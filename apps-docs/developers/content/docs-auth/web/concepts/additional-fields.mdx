---
title: Additional Fields
description: Add typed user fields to sign-up and profile forms.
---

Declare each persisted field in your auth server's user schema, then register its form presentation in `Auth.Provider`. Use the same field name and type on both sides. The client configuration controls rendering and validation; the server validates and persists submitted values.

```tsx title="auth-fields.tsx"
import { Auth } from '@vezham/react/auth'

export const SignUp = () => (
  <Auth.Provider
    authClient={authClient}
    navigate={navigate}
    additionalFields={[
      {
        name: 'department',
        type: 'string',
        label: 'Department',
        required: true,
        signUp: 'above',
        profile: true,
        inputType: 'select',
        options: [
          { label: 'Engineering', value: 'engineering' },
          { label: 'Design', value: 'design' }
        ]
      }
    ]}>
    <Auth.SignUp />
  </Auth.Provider>
)
```

Here `authClient` and `navigate` are the application's stable client and router adapter from [Quick Start](/docs/ui/auth/web/getting-started).

Supported data types are `string`, `number`, `boolean`, and `date`. Choose `inputType` for text, textarea, number, slider, switch, checkbox, select, combobox, date, datetime, or hidden inputs. `signUp` defaults to false; `profile` defaults to true.

Use `defaultValue` to seed sign-up fields. Profile forms read persisted session values. A `readOnly` field is displayed and omitted from submissions.

## Validation

`validate(value)` may return normally or throw an `Error` whose message is shown next to the field. Async validators run after `validateDebounceMs` (300 ms by default). Required boolean fields must be checked. Keep authorization-sensitive fields server-controlled.

Plugins can contribute additional fields. Provider fields with the same name override plugin defaults.
